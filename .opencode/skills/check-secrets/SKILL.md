# Проверка секретов перед коммитом

Обязательный шаг перед `git commit`/`git push` (особенно после работы с конфигами MCP,
env-файлами, скриптами с учётками). Секреты уже утекали в этот репозиторий
(API-ключ TestSprite в `opencode.json`, 2026-10-10) — повторно нельзя.

## Запуск

```bash
bash .opencode/skills/check-secrets/scripts/scan-secrets.sh
```

Скрипт проверяет **staged**-изменения (то, что уйдёт в коммит): ищет типовые паттерны
ключей/токенов по содержимому и запрещает к стейджу `.env*`, `opencode.json`,
`zabbix_dump.json`. Выход `1` — найдено, коммитить нельзя.

## Правила проекта

- `opencode.json` (конфиг MCP с ключами) — **только локально**, в `.gitignore` (см. CONTEXT §5 №20).
  Ключи в нём — через `{env:VAR}`, значение задаётся в `~/.bashrc`/окружении.
- Реальные `.env` (backend/.env и т.п.) — не трекаются; в git только `.env.example`-плейсхолдеры.
- `zabbix_dump.json` (прод-дамп) — в `.gitignore`, не коммитить.
- Учётка Zabbix/бэкенда — в локальном `.env`, в коммиты не попадает.
- Если ключ всё же засветился: убрать из текущего дерева И из истории (filter-branch /
  filter-repo + force push — пример процедуры в истории CONTEXT 2026-10-10), затем
  отозвать/перевыпустить ключ у провайдера (история не считается «чистой», пока
  GitHub хранит старые объекты по SHA).

## Ручная проверка (быстро)

```bash
git diff --cached --name-only                                    # какие файлы идут в коммит
git diff --cached | grep -nE "sk-[A-Za-z0-9_-]{20,}|Bearer [A-Za-z0-9._-]{20,}|ghp_|AKIA|ZABBIX_API_TOKEN=.{8,}"
```
